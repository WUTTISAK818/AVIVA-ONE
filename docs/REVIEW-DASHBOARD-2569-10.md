## 🔍 ความเห็นรายคณะกรรมการ

### 1) ผู้ตรวจสอบภายใน & บัญชี — 6.5/10
- ✅ **Maker-Checker มีจริงและบังคับได้** ในคำสั่งงาน (ผู้สั่ง≠ผู้ปิด) และรายงานประจำวัน (พนักงานส่ง ผู้บริหารรับทราบ) · การตีกลับบังคับเขียนเหตุผททุกครั้ง
- ✅ **บันทึกวิธีรับทราบแยกได้** (`ack_method`: อ่านรายฉบับ / รวมทั้งวัน / เคลียร์ย้อนหลัง) — ของที่เคลียร์ย้อนหลัง 191 ฉบับไม่ปนกับที่อ่านจริง
- 🔴 **บัญชีคู่ยังพิสูจน์ไม่ได้** — `receipts` 0 · `expenses` 0 · `general_ledger` ยังไม่เดิน · ตรวจเดบิต=เครดิตไม่ได้เพราะไม่มีรายการ
- 🔴 **งวดงานผู้รับเหมา 109 งวด เป็น 0 บาททั้งหมด** — แม่แบบงวดงานไม่มีช่องราคา จึงส่งเบิก/อนุมัติ/จ่ายไม่ได้เลย (ตรวจ 7 ต.ค.)
- 🟡 ไม่มี log ว่าใครถาม AI อะไร — ถ้า AI ให้ตัวเลขผิดแล้วมีคนเอาไปใช้ตัดสินใจ ตรวจย้อนไม่ได้

### 2) ความปลอดภัยข้อมูล (OWASP) — 6.0/10 🔴 **หมวดที่ต้องแก้ก่อนขยายงาน**
ตรวจครบ 4 ชั้นตามมาตรฐาน ส่วน B ข้อ 2.1:

| ชั้น | ผล |
|---|---|
| RLS เปิดครบ | ✅ **163/163 ตาราง เปิด RLS หมด ไม่มีตารางไหนปิด** |
| policy ให้ `anon` | ✅ มีแค่ 1 รายการ (`client_errors` INSERT — ตั้งใจ ใช้เก็บ error) |
| policy `{public}` แบบ USING(true) ล้วน | ✅ **ไม่มีเลย** |
| view SECURITY DEFINER | ✅ 3 view GRANT ให้ `authenticated` เฉพาะ SELECT (บทเรียนรอบ #39 แก้แล้ว) |
| GRANT ของ `anon` | ⚠️ เปิดครบทุกสิทธิ์บน 163 ตาราง (ค่าเริ่มต้น Supabase) — **ปลอดภัยอยู่ได้เพราะ RLS เท่านั้น ไม่มีชั้นสำรอง** |

**🔴 ช่องโหว่จริงที่พบ — RLS ของตารางหลักเป็น `USING(true)`:**

| ตาราง | policy | ผลที่ตามมา |
|---|---|---|
| `leads` | `authenticated_read/update/insert` = **true** | พนักงานทุกคนที่ล็อกอิน (รวมพีท/คนสวน) **อ่านและแก้ฐานลูกค้าทั้ง 328 รายได้** · ฟ้าแก้ลูกค้าเดียร์ได้ |
| `work_reports` | `wr_access` = **ALL true** | พนักงานคนใดก็ **แก้/รับทราบรายงานของคนอื่นได้โดยตรงผ่าน API ฐานข้อมูล** — ข้ามการตรวจสิทธิ์ที่ผมทำไว้ใน `/api/reports/review-actions` |
| `notifications` | `auth_all_notifications` = **ALL true** | อ่านแจ้งเตือนรายบุคคลของคนอื่น และลบทิ้งได้ |
| `employee_payroll_config` | กรองแค่ `project_id` | ทุกคนอ่านค่าตั้งต้นวันลาของทุกคนได้ (ไม่มีคอลัมน์เงินเดือน — ความเสี่ยงต่ำ) |

**✅ ที่ทำถูกแล้ว:** `salary_records` จำกัด admin/ceo/hr · `employees.base_salary` ผ่าน `can_view_finance()` · `directives` จำกัดเฉพาะผู้สั่ง/ผู้รับจริง — **พิสูจน์ว่าทีมทำ RLS ที่ถูกต้องเป็น แค่ยังไม่ได้ทำครบทุกตาราง**

🟡 Leaked Password Protection ยังปิด (ค้างมาหลายรอบ — ต้องกดใน Supabase Dashboard)

### 3) สถาปนิกข้อมูล — 7.5/10
- ✅ **ปฏิทินโครงการคือจุดแข็งที่สุด** — 23 ชนิดจาก 15 ตาราง ผ่าน endpoint เดียว การ์ดหน้าหลักกับหน้าปฏิทินใช้แหล่งเดียวกัน ตัวเลขเพี้ยนกันไม่ได้
- ✅ เพิ่งปิดรอยต่อใหญ่ 2 จุดในสัปดาห์นี้: รายงานหน้างาน→ผังก่อสร้าง (v7.71) และ นัดหมาย→ปฏิทิน (v7.74)
- 🟡 **ยังมีรอยต่อค้าง:** งวดงานผู้รับเหมา ↔ การเงิน (ไม่มีราคา) · การจองลูกค้า ↔ ตารางผ่อน (ไม่มีวันครบกำหนด) · ใบสั่งซื้อ ↔ บัญชี
- 🟡 **8 จาก 23 ชนิดในปฏิทินยังว่างเปล่า** เพราะไม่มีใครกรอก (วันหยุดบริษัท · กำหนดแล้วเสร็จ · งวดผ่อนครบกำหนด · นัดส่งมอบ)

### 4) ผู้จัดการโครงการก่อสร้าง — 7.0/10
- ✅ ผังตรงหน้างานแล้ว: A07 95% · V28 80% · V29 80% (หลังแก้ trigger ที่พังมาตั้งแต่ต้น v7.72)
- ✅ ระบบเตือนเองถ้าผังกับรายงานหน้างานไม่ตรงกัน (09:20 น.)
- 🔴 **งวดงาน 109 งวด = 0 บาท ทั้งหมด** ยังเบิกไม่ได้สักงวด · ตรวจงวดงานมี 6 รายการ ยังไม่มีใครกดตรวจ

### 5) ผู้จัดการฝ่ายขาย — 7.8/10
- ✅ ท่อขายครบวงจรและเดินจริง: จอง → อนุมัติเงินจอง → ใบจอง → ตารางผ่อน → สัญญา (ดีลแปลง 29 ฿4,280,000 ผ่านครบทุกขั้นเมื่อ 3 ต.ค.)
