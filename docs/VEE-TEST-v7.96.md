## กลุ่ม B — ลูกค้าที่โอนแล้ว: ล็อก / ปลดล็อก (v7.94)

**5 แปลงที่ปลดล็อกไว้ถึง 31 ต.ค. 69:** แปลง 7 · 13 · 14 · 15 · 16
**แปลงที่ยังล็อกอยู่ (ใช้ทดสอบฝั่งล็อก):** ไม่มีแปลงที่โอนแล้วและมีเจ้าของนอกจาก 5 แปลงนี้ → ใช้วิธี "ล็อกกลับทันที" ในข้อ B4 แทน

### B1 ✍️ · ฝ่ายขายแก้ลูกค้าที่ปลดล็อกแล้วได้จริง
- **เป้าหมาย:** ยืนยันว่าสิ่งที่ฟ้าแจ้งว่าทำไม่ได้ ตอนนี้ทำได้แล้ว
- **ทำ:** ล็อกอินด้วย `sales1@alisa.com` → หน้าขาย → เปิด **แปลง 15 · คุณอ็อฟ คุณแป๋ว น้องรักรัก (CRM-0414)**
- **ผลที่ต้องได้ (ขั้นแรก):** เห็นกล่องสีเหลือง **"🔓 ปลดล็อกให้แก้ไขอยู่"** บอกว่าแก้ได้ถึง 31 ต.ค. 69 และใครอนุญาต
- **ทำต่อ:** กดปุ่มแก้ไข → ใส่ **อีเมล** `test-vee@example.com` → กดบันทึก
- **ผลที่ต้องได้:** บันทึกสำเร็จ ไม่ขึ้นข้อความ "แก้ไขได้เฉพาะฝ่ายบริหาร"
- **✅ วิธีคืนค่า (ต้องทำ):**
```sql
UPDATE leads SET email = NULL WHERE lead_code = 'CRM-0414';
-- ผลที่คาดหวัง: UPDATE 1
```

### B2 · ปลดล็อกไม่รวมการเปลี่ยนสถานะ
- **ทำ:** ยังล็อกอินเป็นฝ่ายขาย → แปลง 15 → ลองกดเปลี่ยนสถานะ
- **ผลที่ต้องได้:** ขึ้นข้อความ **"ลูกค้าที่โอนแล้ว เปลี่ยนสถานะได้เฉพาะฝ่ายบริหาร (การปลดล็อกให้แก้ไขไม่รวมการเปลี่ยนสถานะ)"** และสถานะไม่เปลี่ยน
- **เหตุผลที่ต้องเป็นแบบนี้:** ย้ายสถานะลูกค้าที่โอนแล้วกระทบยอดขายที่รับรู้ทางบัญชีไปแล้ว

### B3 · ฝ่ายขายไม่เห็นปุ่มปลดล็อก
- **ทำ:** ล็อกอินฝ่ายขาย → เปิดลูกค้าที่โอนแล้วรายใดก็ได้
- **ผลที่ต้องได้:** เห็นกล่องสถานะล็อก/ปลดล็อก **แต่ไม่มีปุ่ม** "ปลดล็อก" / "ต่ออายุ" / "ล็อกกลับ"

### B4 ✍️ · ผู้บริหารล็อกกลับได้ และล็อกมีผลจริง
- **ทำ:** ล็อกอิน `wuttisak_p@hotmail.com` → แปลง 15 → กด **"ล็อกกลับทันที"**
- **ผลที่ต้องได้:** กล่องเปลี่ยนเป็น "🔒 ลูกค้าโอนแล้ว — ฝ่ายขายแก้ไขไม่ได้"
- **ทำต่อ:** ออกแล้วล็อกอินเป็น `sales1@alisa.com` → แปลง 15 → กดแก้ไข
- **ผลที่ต้องได้:** ขึ้น "ลูกค้าที่โอนแล้ว แก้ไขได้เฉพาะฝ่ายบริหาร — ถ้าต้องกรอกข้อมูลที่ยังขาด ให้แจ้งผู้บริหารปลดล็อกรายนี้ให้ก่อน"

## กลุ่ม C — ตารางชำระเงิน: ยอดพิมพ์ทับได้ (v7.95)

**ที่มา:** ฟ้าแจ้ง "ตัวเลขไม่สามารถแก้ไขได้ค่ะ ระบบฟิคตัวเลขมาให้เลยค่ะ" (24 ต.ค. 09:55)

### C1 · ยอดงวดที่ยังไม่รับชำระต้องพิมพ์ทับได้
- **ทำ:** เปิด **แปลง 15 (CRM-0414)** → เลื่อนไปหัวข้อ **"ตารางชำระเงินลูกค้า"**
- **ผลที่ต้องได้:** แต่ละงวดที่ยังไม่รับชำระมี **ช่องกรอกยอดเงิน** (ไม่ใช่ตัวหนังสือเฉย ๆ) และมีช่อง **"ครบกำหนด"** เป็นปฏิทิน

### C2 ✍️ · บันทึกยอดที่พิมพ์ทับได้จริง
- **ทำ:** พิมพ์ยอดใหม่ในงวดใดงวดหนึ่ง → ปุ่ม **"บันทึกยอด"** ต้องโผล่ขึ้นมา → กด
- **ผลที่ต้องได้:** ขึ้นข้อความสำเร็จ · ยอดเปลี่ยนตามที่พิมพ์ · **ท้ายตารางอัปเดตยอดรวม** และถ้าต่างจากราคาขายจะขึ้นเตือนสีเหลืองพร้อมบอกส่วนต่าง
- **✅ วิธีคืนค่า (ต้องทำ — จดยอดเดิมไว้ก่อนแก้):** พิมพ์ยอดเดิมกลับแล้วกด "บันทึกยอด" อีกครั้ง
  ถ้าจำยอดเดิมไม่ได้ ดูจาก `audit_log` ซึ่งบันทึก "ยอดเดิม → ยอดใหม่" ไว้ให้:
```sql
SELECT left(description, 120) AS description,
       (created_at AT TIME ZONE 'Asia/Bangkok')::timestamp(0) AS th_time
FROM audit_log WHERE action = 'installment_edit' ORDER BY created_at DESC LIMIT 10;
```

### C3 · งวดที่รับชำระแล้วต้องแก้ยอดไม่ได้
- **ทำ:** หาลูกค้าที่มีงวดขึ้นว่า "รับแล้ว" (ถ้าไม่มีให้ข้ามข้อนี้แล้วเขียนว่า "ไม่มีข้อมูลให้ทดสอบ")
- **ผลที่ต้องได้:** งวดนั้น**ไม่มีช่องกรอกยอด** แสดงเป็นตัวหนังสืออย่างเดียว
- **เหตุผล:** งวดที่รับเงินแล้วลงบัญชีและสมุดรายวันไปแล้ว แก้ย้อนหลังจะทำให้บัญชีไม่ตรง

### C4 · ปุ่ม "♻️ สร้างใหม่" ขึ้นถูกเงื่อนไข
- **ผลที่ต้องได้:** ปุ่ม **♻️ สร้างใหม่** ขึ้นที่หัวตาราง **เฉพาะตอนที่ยังไม่มีงวดไหนรับชำระ** · ถ้ามีงวดที่รับแล้ว ปุ่มต้องหายไป

### C5 · เตือนเมื่อราคาขายดูเหมือนกรอกเป็นล้าน
- **เป้าหมาย:** กันเคสจริงที่ตารางออกมาเป็น **งวดจอง ฿4.50** เพราะราคาถูกกรอกเป็น "4.5"
- **ทำ:** หาลูกค้าที่ยังไม่มีตารางชำระเงิน → ตั้งราคาขายเป็น `4.5` → กด "สร้างตาราง"
- **ผลที่ต้องได้:** ขึ้นกล่องถามว่า *"ราคาขายที่บันทึกไว้คือ ฿4.5 ซึ่งดูน้อยผิดปกติ — ถ้าตั้งใจพิมพ์ว่า 4.5 ล้าน ให้กดยกเลิก…"* → **กดยกเลิก** แล้วตารางต้องไม่ถูกสร้าง
- **✅ วิธีคืนค่า:** ลบราคา 4.5 ที่ใส่ทดสอบออก

### C6 · ไม่มีราคาขาย = ตารางเป็น 0 (ไม่ใช่เอางบประมาณมาใช้แทน)
- **ทำ:** ลูกค้าที่ไม่มี "ราคาขายที่ตกลง" แต่มี "งบประมาณ" → กด "สร้างตาราง"
- **ผลที่ต้องได้:** ทุกงวดเป็น **฿0** และขึ้นเตือนว่ายังไม่มีราคาขาย · **ห้ามเอาตัวเลขงบประมาณมาคิด** (นี่คือบั๊กเดิมที่ทำให้เกิด ฿4.50)

## กลุ่ม E — ช่องวันจอง / วันโอนจริง (v7.96 ข้อ 2)

- **ทำ:** ล็อกอินฝ่ายขาย → เปิดฟอร์มลูกค้า → เลื่อนไปกลุ่มวันที่ (ใต้ "วันกู้ผ่าน")
- **ผลที่ต้องได้:** **ไม่เห็น** ช่อง "วันจอง (ย้อนหลัง)" และ "วันโอนจริง (ย้อนหลัง)"

### E2 ✍️ · ผู้บริหารเห็นและกรอกย้อนหลังได้
- **ทำ:** ล็อกอินผู้บริหาร → ฟอร์มลูกค้า → ใต้ "วันกู้ผ่าน" ต้องเห็นข้อความสีเหลือง 👑 และ 2 ช่อง
- **ทำต่อ:** เปิด **แปลง 13 · CRM-0325 (ครูกล้วย)** → ใส่ "วันโอนจริง" เป็น `2026-06-28` → บันทึก
- **ผลที่ต้องได้:** บันทึกสำเร็จ · เปิดดูใหม่ค่ายังอยู่
- **ตรวจด้วย SQL:**
```sql
SELECT lead_code, booking_date, transfer_date FROM leads WHERE lead_code = 'CRM-0325';
-- ผลที่คาดหวัง: transfer_date = 2026-06-28
```
- **✅ วิธีคืนค่า (ต้องทำ):**
```sql
UPDATE leads SET transfer_date = NULL WHERE lead_code = 'CRM-0325';
-- ผลที่คาดหวัง: UPDATE 1
```

### F2 ✍️ · ใบใหม่ต้องใช้ราคาขาย (ทำเฉพาะเมื่อมีการขายจริงที่จะปิดพอดี)
- **⚠️ ข้อนี้สร้างใบขออนุมัติจริงในระบบ** — **อย่าทำกับลูกค้าสมมติ** ให้รอจังหวะที่ฝ่ายขายจะปิดการขายจริงอยู่แล้ว แล้วค่อยตรวจผล
- **ผลที่ต้องได้:** ใบขออนุมัติสัญญาที่ออกใหม่ มี **วงเงิน = ราคาขายที่ตกลง** ไม่ใช่งบประมาณที่ลูกค้าแจ้ง

## กลุ่ม G — ของค้างจาก v7.92 / v7.93 (ยังไม่เคยทดสอบบนมือถือจริง)

### G1 · ฝ่ายก่อสร้างบันทึกแล้วสถานะการขายต้องไม่หาย (v7.92)
- **ทำ:** หน้าก่อสร้าง → เลือกแปลงที่ขายแล้ว (เช่น แปลง 15) → เปลี่ยน **"สถานะก่อสร้าง"** → บันทึก
- **ผลที่ต้องได้:** กลับไปดูผังโครงการ แปลงนั้น **ยังขึ้นว่าขายแล้วเหมือนเดิม** ไม่กลับไปเป็น "ว่าง"
- **ตรวจด้วย SQL:**
```sql
SELECT plot_number, status AS สถานะการขาย, construction_status AS สถานะก่อสร้าง
FROM houses WHERE plot_number = 15;
-- ผลที่คาดหวัง: สถานะการขาย = sold (ไม่เปลี่ยนไปตามสถานะก่อสร้าง)
```

### G2 ✍️ · ข้ามขั้น "จอง" ไปทำสัญญา แปลงต้องถูกกันไว้ (v7.93)
- **ทำ:** สร้างลูกค้าทดสอบ ตั้งสถานะเป็น **"ทำสัญญา"** โดยไม่ผ่าน "จอง" และผูกกับแปลงที่ว่าง
- **ผลที่ต้องได้:** ผังโครงการต้องขึ้นว่าแปลงนั้น **ถูกกันไว้แล้ว** พร้อมหมายเหตุบอกสถานะจริง เช่น "กันแปลงไว้ — ชื่อลูกค้า (ทำสัญญา)" ไม่ใช่คำว่า "จองไว้" เฉย ๆ
- **✅ วิธีคืนค่า (ต้องทำ):** ลบลูกค้าทดสอบ และคืนแปลงเป็นว่าง — **ส่ง lead_code ที่สร้างมาให้ ONE เขียน SQL ลบให้** อย่าเขียน DELETE เอง (กฎห้าม cleanup SQL ที่ scope ไม่ชัด)

### คืนค่าให้ครบก่อนปิดงาน — ตรวจด้วย SQL ชุดนี้
```sql
-- 1) ปลดล็อก 5 แปลงต้องยังอยู่ครบ ถึง 31 ต.ค.
SELECT lead_code, plot_number, assigned_to, edit_unlocked_until
FROM leads WHERE edit_unlocked_until IS NOT NULL ORDER BY plot_number;
-- ผลที่คาดหวัง: 5 แถว — แปลง 7 · 13 · 14 · 15 · 16 ทุกแถว edit_unlocked_until = 2026-10-31

-- 2) ไม่มีค่าทดสอบตกค้าง
SELECT lead_code, email, transfer_date FROM leads
WHERE email LIKE '%test-vee%' OR lead_code IN ('CRM-0414','CRM-0325');
-- ผลที่คาดหวัง: CRM-0414 email = NULL · CRM-0325 transfer_date = NULL · ไม่มีแถวอื่นโผล่มา

-- 3) ยอดงวดของแปลง 15 กลับเป็นค่าเดิม
SELECT installment_no, name, amount FROM customer_installments ci
JOIN leads l ON l.id = ci.lead_id WHERE l.lead_code = 'CRM-0414' ORDER BY installment_no;
-- ผลที่คาดหวัง: ตรงกับยอดที่จดไว้ก่อนเริ่ม C2
```
